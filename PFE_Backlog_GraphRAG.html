1.3 Acteurs du système

👨‍💻
Developer

Ouvre des PRs, consulte Insights + analytics + All PRs, travaille dans son Workspace, reçoit les notifications

🎯
Tech Lead

Contrôle les reviews, gère les équipes, configure les paramètres de revue, applique les décisions (Approuver / Bloquer / Assigner)

🔐
Admin

Administre la plateforme, configure la KB / RAG, gère les politiques, les utilisateurs et les intégrations

🤖
Système IA (GraphRAG)

Indexe les repos, analyse en double parallèle (statique + GraphRAG), génère des findings editor-ready ancrés dans Neo4j et la KB

1.4 Corrections architecturales

Incohérence détectéeCorrection appliquée
Qdrant comme vector storeSupprimé — Neo4j est l'unique store (graphe + vecteurs natifs)
RAG classique (cosinus seule)GraphRAG : FTS symbolique + traversée multi-hop + sous-graphe + KB
Chunking naïf par tokensChunking AST-aware Tree-sitter (fonction / classe / module)
Re-indexation complète à chaque PRIndexation incrémentale (fichiers modifiés uniquement)
Contexte repo en priorité pour la générationPriorité inversée : KB rules → graphe → repo
Analyse statique et GraphRAG séquentielsDouble analyse parallèle fusionnée avant la sortie
Commentaires génériques sans traçabilitéCommentaires editor-ready avec fichier + ligne + preuve + règle

5.1 Spécification Fonctionnelle

Pipeline GraphRAG en 7 couches (Étape 4 — branche droite)

(1) FTS symbolique Neo4j sur entités du diff · (2) Traversée CALLS/IMPORTS/DEPENDS_ON/HAS_RULE · (3) Multi-hop depth 2–3 · (4) Extraction sous-graphe (max 50 nœuds) · (5) KB Rule lookup (VIOLATES/HAS_RULE) · (6) Reranking cross-encoder optionnel · (7) Assembly : KB rules (P1) → graphe (P2) → chunks repo (P3).

Génération ancrée provider-agnostique

Interface LLMProvider : OllamaProvider / ClaudeProvider / OpenAIProvider. Config via LLM_PROVIDER env var. Même StructuredReviewOutput pour tous. Réparation JSON auto. Guardrails : ≥1 evidence_ref (Neo4j node ID ou KB doc ID) par finding obligatoire.

Commentaires editor-ready + Auto-fix (Étape 6)

Format : {file_path, line_start, line_end, severity, summary, why_it_matters, evidence_refs, rule_refs, auto_fix}. Affichés dans Code editor Dev et TL (remplacement des placeholders Sprint 2). Auto-fix : diff-like actionable ou null.

Rapport structuré GraphRAG + Classification (Étape 5)

Résumé ancré KB+graphe. Risque = agrégation statique+GraphRAG. Tests basés sur CALLS identifiées. Merge readiness = risque × couverture règles KB. Classification auto bloquante/majeure/mineure → Reviews Queue TL.

Insights Developer

Analyse AnalysisRun Neo4j (30 derniers jours). Top 5 rules violées par symbole/fichier. Recommandations personnalisées basées sur VIOLATES. Graphique tendance dans page "Insights" du dashboard.
